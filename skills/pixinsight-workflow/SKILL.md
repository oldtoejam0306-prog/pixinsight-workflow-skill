# PixInsight 实测精修工作流

用素材中已有信号获得细节、色彩与自然过渡兼顾的成片。通过用户已接入的 PixInsight MCP 实际处理、测量和看图；参数选择必须有本次素材的试跑依据。用户说“直接等成品”时自主完成候选比较与交付，不逐步索要审美确认；最新明确要求优先。

## 入口与分支

先区分只读汇报、流程设计、继续修图与正式处理。“先汇报再做”先说明进度、问题和下一步；仅要求汇报/设计时不操作图像。

- 实际执行前读 [MCP 操作与恢复](references/mcp-execution.md)，重新确认连接与目标实例。
- 原始 lights、校准帧、WBPP 或重叠加：读 [预处理与开源参考](references/preprocessing.md)。已验证的线性 master 直接进入后期，除非用户要求重叠加或发现源头问题。
- 窄带与多片拼接：读 [SHO 与马赛克](references/sho-mosaic.md)。
- 宽带及反射星云尘埃：读 [LRGB 精修](references/lrgb-dust.md)。
- 需要匿名案例经验时，按需读 [案例与出处](references/case-notes.md)。

先检查用户路径、头信息、历史和检查点，避免重复询问。STF 只是显示拉伸，不能凭屏幕发亮判定非线性。缺失且会改变处理结果的信息才询问，可同时进行独立盘点。

## 可选起始风格

以下仅作为可选的起始风格参考，不能视为所有用户的默认偏好。当前用户明确表达的偏好与本次任务目标优先：

- 充分利用素材已有细节，以“每日一图”的完成度为审美目标；不承诺入选，不生成虚构结构。
- 暗云气/尘埃结构清楚、亮度适中，保留暗带；不把背景整体抬灰或靠压黑隐藏问题。
- 星云色彩丰富、内部层次清楚；亮核心不能因融合或拉伸变成一片白。
- 星云与星点分开修；星点要有足够亮度、存在感与星色，不一律缩星或压星。
- 核心到外围的亮度、色相和局部对比过渡柔和，避免蒙版边界与光环。
- 只有当用户希望强调目标中已有的局部色彩时，才考虑柔和增强；不为所有目标套用固定色相，也不增强亮星色边或背景色噪声。
- 样图用于理解色彩和层次，考虑视场、曝光及滤镜差别，不把样图像素移入实拍成片。

## 开始处理前

1. 确认目标、输入阶段、单色/CFA/RGB、通道/面板关系、裁切、曝光与校准状态。区分总曝光、每片/每通道曝光和加权有效曝光。
2. 原始素材只读，输出到目标专属目录。恢复时实际验证检查点可打开、阶段正确；目录存在不代表处理成功。
3. 确认 PI/MCP 响应，按需核实插件和 AI 模型实际执行、Gaia/MARS 可访问与覆盖。构造器存在不等于已跑通。
4. 检查可用内存、PI 占用和相关磁盘余量，考虑全图、通道、蒙版、历史及快照开销，不一次打开所有候选。
5. 固定比较区：核心、暗云气、低信号背景、亮星/光晕、边角；马赛克加接缝。背景区要看图确认，不能把满场尘埃当空天。

## 实测选择闭环

采用“问题假设 → 基线 → 少量候选 → 实际执行 → 测量与目视 → 选择 → 全图复核”。

1. 诊断先作为假设。背景色块可能来自校准、梯度、拼接、拉伸或色度增强，不能只凭外观断定 DBE 失败。
2. 查询当前 Process 参数与输出设置，显式设置关键值，不依赖上次界面状态。保留不处理基线；通常两三档足够，有新证据才扩大搜索。
3. 细节与降噪先用原生分辨率代表区域；整体色彩/构图可缩略筛选。依赖全局统计、WCS 或背景分布的处理仍需全图验证。
4. 候选使用相同区域、缩放、色彩管理与比较用显示拉伸；不分别 auto-STF 后直接判优。比较拉伸路线时可对齐显示亮度，但另查各自真实黑白场与裁切。
5. 核验调用结果、目标/新窗口、像素变化和文件。像素处理统计完全相同则检查实际输出与像素差异、排查 no-op；WCS/历史/保存等非像素操作按其预期结果验收。
6. 噪声用 MRS 或适合区域的稳健估计并说明局限，不用整图标准差代表噪声。结合星点、跨区色差、饱和、裁切和 1:1 纹理，单一指标不能替代看图。
7. 记录选中/淘汰理由。更强参数无明确收益就选较轻者；振铃、蜡化、色斑、去星空洞或蒙版边界出现时回退，不继续堆处理掩盖。
8. 选定后应用全图。缩略图上的半径、羽化和坐标蒙版须按尺度换算再检查，不照搬旧目标样点或中心位置。

一次比较及针对性细调仍无可靠改善，就保留最佳已验证版本并说明限制，不无限试参数。执行者必须实际运行和看图，辅助评审不能替代此闭环。

## 负荷、清理与续接

- 一个 PI 实例同时只运行一个处理任务；候选顺序生成。保留基线、当前优胜者与必要工作图层，大图阶段前后检查负荷。
- snapshot 占内存且不能替代磁盘检查点。关键 XISF 保存验证后，关闭本任务淘汰窗口/快照，保留用户原有未保存窗口。
- 沿用目标目录；按需建立 `linear/`、`candidates/`、`review/`、`final/`、`metadata/`、`logs/`、`scripts/`。
- 记录生成物用途、依赖和是否可重建。下游检查点成功后清理明确淘汰的临时图、重复预览和缓存；保留原始素材、有效校准 master、可恢复检查点、选中图层、配方和回执。Drizzle 等后续依赖不可提前删除。
- 删除前确认绝对路径处于本任务输出根内，排除 junction/symlink 外指；按明确文件清单使用 PowerShell `Remove-Item -LiteralPath`，不跨 shell 拼删除命令。归属不清就保留，不删整个摄影目录。
- 当前系统阻止操作时，如实报告未完成步骤，不尝试绕过拦截。
- 长阶段保存输入、输出路径/视图、实际参数、完成状态和下一步，重启后从文件恢复。进度报告给出已验证阶段，不猜测百分比。

## 交付

整体与 1:1 检查核心、暗云气、亮星、背景、边角/接缝，查看色块、过渡、裁切、纹理、伪影、去星残留和星点合成。保存后实际打开或解码检查尺寸、位深、色彩配置与非有限像素；区分抽查和全量检查。

通常交付 32 位浮点 XISF、独立无星/星点层、16 位 TIFF、sRGB 全图与轻量预览。先实际转换到 sRGB 再写匹配 ICC，不只换标签。几何变化后核验/更新 WCS，或明确失效。

处理记录保存输入来源、版本、实际配方、检查点、选择理由、验证、清理与限制。克隆/PixelMath 可能无法继承完整历史，需单独保存参数和合成后步骤，让图层重组能解释最终母版。

最终提供可点击文件链接，说明主要改进与未完成项。“已生成”“代理检查”“用户认可”分别记录；没有用户反馈不标为用户验收。
